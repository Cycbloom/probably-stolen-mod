# 垃圾场拾荒地图 · 0.3.9

夜间外出 → 城市地图选「垃圾场」→ 点「前往」时先打开本 mod 的作业地图，选一块地标、点「进入该区域」，才真正进入垃圾场；进入后点「拾荒」直接按该区权重拾取，本次停留内不再询问。离开垃圾场（回家、去别的地点、重新进入）后再来，需要重新选一次。取消或返回键关闭地图。选择只在本次停留内有效，不写入存档。

## 掉落设置

地图窗口底部不再有设置按钮，全部调节都在游戏的**模组设置窗口**（模组列表里本 mod 的「设置」）里，形态与原生条目一致：四条全局滑条。每条滑条的数值直接显示在滑条右侧的同一行，不再另起一行。

| 设置 | 范围 | 默认 | 说明 |
|---|---|---|---|
| 垃圾出现率倍率 | 0–200% | 100% | 按概率缩放：50 表示该区垃圾概率减半，让出的份额按原比例分给其它物品 |
| 高档物资出现率 | 0–30%（步长 0.5） | 0% | 每次拾荒抽到高档物资的总概率，从非垃圾物品按比例让出（垃圾份额不受影响） |
| 高档保底 | 0–20 次 | 0（关） | 连续这么多次没出高档，下一次必出；出任意高档即清零 |
| 区域专精度 | 0–100% | 0% | 四个区共用一条。决定这一趟捡到的东西里、除垃圾之外有多少是本区才有的特色物品：0% 保持默认混搭，越高外地的普通物品越按比例让位给本区特色物品，100% 时除垃圾外只出本区的东西；垃圾不受影响 |

原来的「偏好类别」跨区下拉已删除：地点本身就是主题，再叠一个全区通用的类别只会让两个区域变成同一种出产。0.3.7 起，原先四个区各一条的区域专精度滑条也合并成上面这一条——既然不分区域，就不再逐区设置。

### 区域专精度怎么算

设区域专精度为 f（0–100%），四个区共用同一个 f，但各用自己的一份特色清单（入口空地 = 材料 + 工具 + 日用；拆解堆 = 材料 + 工具 + 模组；生活废料带 = 日用 + 食品 + 医疗；报废终端区 = 模组 + 电子件）。f 只作用于**非垃圾物品**：属于本区特色类别的物品权重不变，其余非垃圾物品权重乘以 (1 − f)。垃圾是单独一档，权重不参与这一步。

之后按固定顺序合成概率：

1. 垃圾概率 = 基础表里该区垃圾占比 × 垃圾倍率（与 f 无关，与高档也无关）。
2. 高档物资总概率从**非垃圾物品**里按比例让出，不再动垃圾。
3. 剩下的份额按权重分给非垃圾物品：f = 0 时就是默认混搭，f = 100 时只剩本区特色物品。

因此垃圾出现率在任何区域专精度下都等于「基础占比 × 垃圾倍率」；f 只改变「除垃圾外，捡到的东西里有多少是本区特色物品」。同一条 f 下四区各自的结果（默认其它设置，垃圾倍率 100%）：

| 区域 | f = 0% | f = 50% | f = 100% | 区域特色 | 垃圾概率（各档相同） |
|---|---:|---:|---:|---|---:|
| 入口空地 | 12.26 | 12.13 | 11.90 | 材料 / 工具 / 日用 | 48.8% |
| 拆解堆 | 12.26 | 12.37 | 12.49 | 材料 / 工具 / 模组 | 51.9% |
| 生活废料带 | 12.26 | 12.20 | 12.13 | 日用 / 食品 / 医疗 | 43.7% |
| 报废终端区 | 12.26 | 13.34 | 16.72 | 模组 / 电子件 | 68.0% |

价值只是小幅变化，因为垃圾与其他物品的份额没有被互抢：区域专精度是「纯度」滑条，不是「收益」滑条。终端区升得最多（非本区的杂项让位给了模组与电子件），入口空地与生活废料带略降（被让位掉的食品/工具/模组本身比本区的日用品值钱一点），拆解堆基本持平。

### 调节与写盘

滑条是唯一输入方式（避免两个输入源互相覆盖）。步长：垃圾 1%、高档 0.5%、保底 1 次、区域专精度 1%。拖动过程中，滑条右侧的数值与下方四区对比逐帧刷新，但只在松手（PointerUp）或点窗口底部「应用」时才写模组配置；松手事件丢失时会在下一次拖动开始或点「应用」时补写。四个预设按钮（默认 / 专精拉满 / 稳妥保底 / 赌高档）由本 mod 注入在四区对比下方，点击后同时驱动四条滑条的位置与读数；「重置」沿用游戏窗口自带的按钮（把控件复位到默认，再点「应用」生效）。

- 默认：垃圾 100% / 高档 0% / 保底关 / 区域专精度 0%
- 专精拉满：区域专精度 100%
- 稳妥保底：高档 3% / 保底 10 次
- 赌高档：高档 8%

### 界面结构

注入方式：`ModConfigWindow.BuildEntry` 的 prefix 记录当前条目与 builder，postfix 在该条目原生行结束后追加本 mod 的行；另外补丁 `CustomUIElement.SetFixedWidth`，在原生代码给滑条定宽（同一行尚未结束）的那一刻，把数值标签插进这一行滑条之后，所以数值和滑条在同一行、位于滑条右侧。原生滑条预制体没有自带数值文本组件（Assembly-CSharp 里不存在监听 onValueChanged 的 SliderValue 之类组件，滑条分支只传了 null 回调和 224 宽度），因此只能这样在同位置补一个标签；若该补丁因为游戏版本变化失效，会自动退回「数值单独一行」的旧形态，不会丢读数。

界面顺序：垃圾倍率（右侧数值）→ 高档出现率 → 高档保底 → 区域专精度 →「每次拾荒大约能捡到的物品价值（拖动时实时刷新）」标题 →「本次：改了什么」→ 四区「默认 x.xx → 现在 y.yy（±z%）」四行 → 四区平均 → 四个预设按钮。四区那四行是「同一个区域专精度下，各区各自的结果」，所以拖动这一条滑条时四行会一起变。

0.3.3 修复保留：PointerUp 触发器只挂在持有 `Slider` 组件的那个物体上；挂到子图形上会让 `EventTrigger` 抢走按下与拖动事件，滑条收不到 `OnDrag`。诊断日志前缀 `[DGM-SLIDER]`：注入时打印每条滑条的绑定与范围，拖动开始/结束各一行，拖动中每 0.25 秒一行（含回调计数与首区价值）。

高档物资池（价值 250–400，按 `unitValue`）：蓝血、高级滤芯、便携净水器、高端瓶装水、黑色注射器、稀有电子件、高级模组提取器；各区的具体分布不同。高档物资不受区域专精度影响，它本身就是稀有掉落。

### 掉落表审查（0.3.9）

四个区的基础表与高档池逐项核对过 `Assembly-CSharp` 里的物品定义（`*ItemDirectory` 的注册标签、`EnableTag` 参数、`Init*Helper` 调用与 `SetSpriteAndShape` 的形状名），移除了两件不属于随机垃圾的东西：

| 物品 | 游戏内名称 | 依据 | 处理 |
|---|---|---|---|
| `luxury_supply_crate` | 给埃莉诺的慰问包裹 | `ContainerItemDirectory` 容器；`EnableTag("IMPORTANT_TAG")`；外观形状 `eleanor_box`（埃莉诺的盒子）；`StolenHelper.InitStolenItem` 标记为他人所有 | 移除（剧情物品，不是「奢侈品补给箱」） |
| `chem_scanner` | 成分光谱仪 | `MedsItemDirectory`；定义了 `maySelectSlotItemFunc / canSelectSlotItemFunc / mayThisTargetItemFunc / canThisTargetItemFunc / onItemTargetItemFunc` 一整套「对背包内其它物品使用」的检测逻辑，并带 `CAN_USE_ON_NON_OWNED_TAG` | 移除（功能装置，用途是拆解鉴定，不是可回收垃圾） |

基础表 53 项全部是普通材料 / 工具 / 日用 / 食品 / 药品 / 制式武器 / 模组，没有任何一项带 `IMPORTANT_TAG`、`CONTAINER_TAG` 或容器 / 检测器 / 装置类回调，因此一项未删。高档池由 9 件减为 7 件，各区权重按原比例保留（只去掉被删的两项），高档总概率与基础表概率不变。

## 掉落权重

每个区域有一张独立的「物品 → 权重」表，概率 = 该物品权重 ÷ 该区权重总和。四个区域不是同一张表换倍率，而是分别配置了不同物品的权重。

| 地标 | 定位 | 主要构成 |
|---|---|---|
| 入口空地 | 通用杂项 | 垃圾约 49%，材料、工具、日用、食品、药品各有一点 |
| 拆解堆 | 材料与工具 | 材料与工具占比最高，模组约 3% |
| 生活废料带 | 日用与消耗品 | 日用、食品、药品为主，垃圾约 44% |
| 报废终端区 | 模组与电子件 | 垃圾约 68%，但模组 + 电子件比例全场最高 |

归一化方式：先把各物品权重设为相对整数，再解出「垃圾」的权重，使该区单次拾荒的价值等于原版 `dumpingGroundTG` 的价值（约 12.26）。因此默认设置下四个区域的价值几乎相同，差异只体现在「捡到什么」。

物品价值取数：游戏代码中 `GameItem.unitValue` 字段（`SetValue` 的满盒物品按内容折算：10 条检测条 + 盒子 = 31，9 片净水片 + 盒子 = 55；`random_*_module` 按生成的基准模组 70 计）。

四个区域默认值（单次拾荒，已按整数权重实算）：

| 区域 | 默认价值 | 相对原版 |
|---|---:|---:|
| 入口空地 | 12.260 | ±0.0% |
| 拆解堆 | 12.261 | +0.0% |
| 生活废料带 | 12.260 | ±0.0% |
| 报废终端区 | 12.263 | +0.0% |

最大差异 0.03%，远小于 10%。

## 告示板

地图上每个地标下方有一块「告示板」按钮。点开后可看到该区全部物品的当前概率（含掉落设置里的倍率、区域专精度与高档池），按概率从高到低排列；概率取整到 0.1%（≥10% 时取整数百分比），并显示该区当前价值。默认设置下与基础权重表逐项一致；夜间事件（如垃圾事件）会在运行时临时抬高「垃圾」的权重，四区共享同一处理方式：只缩放垃圾，其余物品按比例让位。

## 兼容性

区域只在玩家确认后，作用于本次原版垃圾场的普通掉落组 `dumpingGroundTG` 中「主掉落」的那一次抽取。受伤、空手、拾荒次数、背包发现及工具额外掉落由原玩法和原有 Mod 照常结算。`ModHook.OnLootRolled` 仍会以对应的原版表名触发。

旧配置文件里的 `theme` 条目不再读取，也不会显示；留在配置里无副作用。

0.3.7 起，旧的四条 `focus_gate / focus_scrap / focus_refuse / focus_terminal` 同样不再读取，改为单一 `specialty` 条目；旧值留在配置文件里无副作用。0.3.8 只把这条设置的中文名改为「区域专精度」，配置键仍是 `specialty`，已保存的数值继续生效。

编译：在 PowerShell 运行 `./build.ps1`，生成 `dist/`。运行 `./build.ps1 -Install` 同时放进本地 `Mods/DumpingGroundMap/`。底图已包含；改图后可用 Pillow 运行 `python draw_map.py` 重新生成。

## 版本与提交约定

本目录是一个独立的 Git 仓库（首个提交为 0.3.9，之前的历史已被覆盖，无法回溯，不要伪造）。`dist/` 是构建产物，不入库。

- **一次改动一个提交**：一个功能、一个修复、一次数值调整各提交一次，不要混在一起；提交前先跑 `./build.ps1` 确认能编译。
- **首行格式**：`<版本号> <类型>: <一句话主题>`，例如 `0.3.9 fix: 高档池移除剧情与装置类物品`。类型用 `feat` / `fix` / `tune` / `docs` / `build`。
- **正文写原因**：说明为什么改、影响哪些设置项或数值、验证方式；纯文案改动也要写一句原因。
- **版本号**：每次要发布给游戏用的构建递增 `manifest.xml` 里的 `ModVersion`，并在最后一个提交打 `vX.Y.Z` 标签（如 `v0.3.9`）。同一版本内的多次未发布提交可共用当前版本号。
- **发布流程**：改版本 → `./build.ps1` → 提交 → `git tag vX.Y.Z` → 关闭游戏后部署到 `Mods/DumpingGroundMap/`。
- 掉落权重与收益的详细推导在仓库内的 [`docs/掉落权重与期望收益.md`](docs/掉落权重与期望收益.md)，改数值时与本 README 的表格一起改。
